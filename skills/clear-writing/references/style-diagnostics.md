# 表达诊断

这一页处理“读着像 AI”“翻译腔”“绕”“空”的问题。先诊断全篇，再看段落，最后看句子和词。不要从第一个不顺眼的词开始逐句替换。

## 先定是不是问题

同一个形式在不同文体里可能是优点：

- 技术术语不能为了通俗而换掉。
- 法律、合同、政策中的限定和责任不能删。
- 正式通知的敬语、致辞的气势、客服的分寸，是文体功能。
- 操作步骤的编号、表格的字段、参考文档的固定结构，是查询工具。
- 真正的三项并列、必要的被动句、精确的长限定，都可能比短句更清楚。

判断标准不是“像不像人”，而是读者是否因此更难找到、理解、相信或执行。

## 全篇层

### 结构错位

表现：

- 开头铺很久背景，结论藏在最后。
- 读者要执行，文章却一直在讲原理。
- 读者要决策，文章却只列功能，没有取舍和风险。
- 操作文档、参考文档和解释文档混在一起。

处理：先回到读者任务，重排章节，不要靠润色句子解决。

### 重复总结

表现：

- 标题说一遍，开头再说一遍，段末再总结一遍。
- 摘要、正文、结语反复讲同一结论。
- 每节都套“背景—分析—小结”。

处理：一个结论只在一个层次承担主要表达，其他位置引用或省略。

### 模板压过内容

表现：

- 每个小节都有标题，但有些小节只有一句空话。
- 所有内容都被拆成列表，论证关系消失。
- 固定章节齐全，读者却找不到真正的问题和答案。

处理：删除无内容的章节，把有因果和取舍的内容写回段落。用户或团队模板必须保留时，在模板内写清具体内容。

## 段落层

### 一段多个中心

一段里同时讲背景、方案、风险、下一步，读者不知道重点。按“一个主要意思”拆段，或把次要内容移到相应章节。

### 论证缺环

只有判断，没有事实；或只有事实，没有解释它为什么支持判断。分析段落至少要让读者看见：

判断 → 证据 → 解释 → 结论或影响。

不是每个段落都要四步齐全，但关键判断不能只靠形容词。

### 抽象名词堆叠

表现：

> 通过对系统进行全面的分析与评估，实现了对相关问题的有效识别与处理，进一步提升了整体稳定性。

问题：谁做了什么、发现了什么、处理了什么、稳定性怎么变化，全都没有。

处理：把动作还原成动词，把结果具体到材料和证据允许的程度。原文没有数字，不要补数字。

更清楚：

> 我们分析并评估了系统，识别并处理了相关问题，整体稳定性得到提升。

原文没有日志、问题数量或运行数据，不能补；这里只把名词化动作还原成动词，保留“整体稳定性提升”的原判断。

## 句子层

### 万能动词加抽象名词

常见形式：

- 对……进行分析 / 研究 / 评估 / 优化
- 作出贡献 / 作出反应 / 作出决定
- 实现提升 / 实现增长 / 实现覆盖
- 进行验证 / 进行处理 / 进行确认

先问真正的动作是什么：

- 分析日志，不是对日志进行分析。
- 验证配置，不是对配置进行验证。
- 决定延期，不是作出延期的决定。

有些固定说法已经自然化，不必机械替换。判断标准是动词是否真的承担了动作。

### 动作链过长

表现：

> 通过引入缓存，将热点数据前置到内存，从而降低数据库压力，进而提升接口响应速度，最终改善用户体验。

一句话里有引入、前置、降低、提升、改善五个动作，读者很难知道哪个是主要机制。

处理：拆开动作链，写清因果。原文没有测过响应速度，就不要把“改善体验”写成已实现结果。

### 主语和动词隔得太远

长定语、插入语和从句把主语和动词拆开，读者读到动词时已经忘了谁在做。先把主干写出来，再补限定。

### 旧信息和新信息位置不对

句首应该承接读者已知的信息，句末放要强调的新信息。每句都用全新概念开头，读者会觉得跳。

### 指代不清

“它”“这个方案”“上述机制”可能指多个对象。把指代对象写出来，或在前一句明确唯一的先行词。

### 同义反复

相邻两句各说半句同一个意思。把两句合起来，看信息有没有减少；没有减少就合并。

## 词语层

### 空泛判断

常见：

- 具有重要意义。
- 有效提升了整体水平。
- 进一步完善了相关机制。
- 在一定程度上解决了问题。
- 值得关注 / 值得深思 / 不难发现。

如果后面没有具体事实，这些词只是抬调子。删掉，或换成材料支持的具体判断。

### 假权威

“研究表明”“业内普遍认为”“大家都知道”没有来源，读者无法核对。要么给出出处，要么改成作者判断并说明依据。

### 装饰性词汇和比喻

为了显得深刻而用“画卷”“织锦”“交响”“灯塔”“基石”“洪流”“底色”“注脚”“时代浪潮”等词，通常会把具体问题变模糊。比喻只在帮助读者理解陌生概念时使用；比喻比原概念还陌生，就删。

### 生造词

能用现成词就用现成词。为了显得凝练而自造术语，通常会让读者多查一次概念，却没多得到信息。确实遇到现有词汇覆盖不了的新概念时，可以造词，但要满足三个条件：

- 第一次出现时，用一句大白话解释它是什么。
- 全篇固定用这一种叫法，不反复换词。
- 不把未经解释的自造词放进标题，也不靠它撑起论证。

这不是要求一篇文章只能造一个词，而是要求每个新词都承担明确概念，不把普通意思包装成新术语。

### 姿态不对

两种姿态都会让读者反感：

- 抬高自己：“很多人没搞懂，而我早就看透了”“大厂都没想明白，但我……”。读者要看观察、机理和证据，不需要作者先宣布自己高明。
- 讨好读者：“好问题！”“您说得太对了”“这是一个很好的观点”“希望这对您有帮助”。这些是聊天机器人垫话，不是内容，删掉，直接说事。

平视就够了。不居高临下，也不一味捧场；把事实、判断和依据摆出来，让读者自己得出结论。

### 中英混杂

有通用中文名的概念用中文；读者日常就用英文的术语可以保留。不要同一段里反复切换叫法，也不要用英文缩写掩盖没想清楚的含义。

### 动词、形容词和对象配不上

动词和形容词要配得上它的主语。随手抓一个听着有力的词，套到它不能形容的对象上，读着别扭，也经不起推敲。

- “账”只会亏空、算不过来、补不上，不会“绷”也不会“崩”。
- “趋势”会延续、会逆转，不会“塌陷”。
- “制度”会失灵、会松动，不会“生锈”。

判断方法：把动词或形容词和它的主语拎出来，问“这个动作或状态，这个东西真做得出来吗”。做不出来，就换一个配得上的词。不要为了有力牺牲准确；张力靠事实和判断，不靠硬套猛词。

## 中文欧化

余光中批评过“万能动词 + 抽象名词”、过量介词、过长定语和滥用被动。这些现象今天仍然常见，但不能把所有欧化都当病。

下面这些句式值得检查，但不是见一个删一个：

| 现象 | 先问什么 | 可以怎么处理 |
|---|---|---|
| “前者 / 后者”回指 | 读者是否需要回头找指代对象 | 重复具体主语，通常比代词回指清楚 |
| “被”字句过多 | 施事是否重要，删掉“被”后意思是否仍清楚 | 施事明确时改主动；受事或责任需要突出时保留 |
| “当……时”“在……的过程中” | 时间或过程框架是否提供必要信息 | 不影响精确限定时，直接说动作和条件 |
| “作为……”开头 | 身份或角色是否真的影响判断 | 需要说明身份时保留，否则直接写主语和动作 |
| “是……的”判断句 | 句子是在下定义、强调，还是只在说性质 | 定义和强调可以保留；普通性质判断可改成直接谓语 |
| “最……之一” | 是否真的存在一个可比较的集合 | 有明确范围时保留；范围不明时写清比较对象或改成具体判断 |
| 长定语套在“一个 / 一种”后面 | 修饰语是否承担必要限定 | 先把主句说清，再补条件或另起一句 |
| “化 / 性 / 度”后缀密集 | 这个抽象名词是否比原动作更精确 | 有确切术语含义时保留；只是把动词名词化时还原动作 |

判断方法：

1. 这句话用中文习惯能不能说得同样准确、同样有劲？
2. 欧化结构是否承担了必要的精确限定？
3. 删掉结构后，意思有没有变模糊？

能说得更自然且不丢信息，就改；中文本身说不清、必须借这个结构，就保留。已经归化的表达，例如某些代词分工和连词，不必清除。

遇到拿不准的翻译腔，可以做一个可选的“回译”检查：把这句话默读成英文，如果几乎逐词对应一个英文模板，中文读起来又别扭，就检查是不是在硬套英文骨架；如果英文需要意译才能对应，通常说明中文本身是顺的。这个检查只用于疑难句，不逐句跑，也不能当成自动判决。

## 结构与对仗

机械编号、三段式、对仗和排比本身不是错。它们可能是：

- 操作步骤的顺序。
- 法规条款的引用。
- 正式文案的气势。
- 真正的三项并列。
- 工具说明、检查表和索引里的导航编号。

要处理的是“用形式冒充内容”：给每个观点硬凑三个，给每节加没有信息量的编号，或者用“不是 X，而是 Y”反复制造翻案感。盖住并列项，只留最要紧的判断，看读者是否少理解了东西；不会少，才考虑删。

## 诊断顺序

1. **全篇**：读者任务、章节顺序、重复和缺口。
2. **段落**：中心、论证、过渡、列表是否替代了分析。
3. **句子**：主语动词、旧新信息、动作链、指代。
4. **词语**：空话、假权威、装饰、术语和中英混杂。
5. **字面**：标点、数字、格式、受保护跨度。

每次修改都要能说出“治了哪个问题”。如果只是“我觉得这样更好”，先放回原样。

## 脚本的作用和边界

`scripts/clarity_check.py` 只做提示：

- 中文正文里的半角标点。
- 万能动词加抽象名词。
- 空泛元话语。
- 机械编号标题。
- 长句、长段、重复开头。
- “不是 X 而是 Y”等结构信号。

它不能判断：

- 这句话是不是在引用原文。
- 这个术语是不是必须保留。
- 这个三项并列是不是有效。
- 这段文字是不是 AI 写的。
- 读者能不能真正理解。

脚本命中不等于必须改；脚本零命中也不等于文章清楚。
